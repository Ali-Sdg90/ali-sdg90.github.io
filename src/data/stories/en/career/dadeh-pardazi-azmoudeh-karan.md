I joined Dadeh Pardazi Azmoudeh Karan in July 2024.

I first heard about the company through one of my former coworkers. The company needed a frontend developer who could build one of its projects from scratch, and my former coworker introduced me to them.

After they reviewed my resume, I had a few meetings with them. I showed them some of the projects I'd built before, and we talked about my experience and what I knew. Eventually, we agreed that I'd also complete a practical test, and if everything went well, they would give me the main project.

The product we were going to build was a large system for restaurants and people looking for work in the industry. Restaurants could manage their information, employees, and job openings, while applicants could create profiles and resumes and send them to restaurants.

A large part of the system was an admin panel that needed to be built from scratch. The designs for many of its pages weren't ready yet either, and they were going to be completed alongside development.

We used React and Ant Design for the frontend.

I already had experience with React, but I didn't know Ant Design very well. So I spent around a month working on a test and practice project, both to get familiar with the library and to give the company a chance to see how I worked.

During that time, I worked with different Ant Design components, built page structures and forms, and practiced working with Postman and API requests. I also regularly delivered the results of my work to the company.

After that stage, they gave me the main project.

The development team consisted of two people. I was responsible for the entire frontend, while another developer, who was around my age, was responsible for the backend.

This was the first real, large React project where I was fully responsible for the frontend from beginning to end.

I had to build everything from the login page and OTP authentication to the main dashboard, restaurant lists, individual and restaurant profiles, the resume builder, image and file uploads, and many other sections and features.

It was a large project, and building it took around seven months in total.

I remember reaching points throughout development where I would run into a wall and have no idea how to build the thing in front of me. I'd go read about it, try different approaches, learn how it worked, and then implement it in the project.

One of the things I cared about from the very beginning was the structure of the project.

I usually either don't do something at all, or, if I do it, I want it to be as organized and well-built as I can make it.

This project was going to have a lot of pages, components, and features, so from the start I paid close attention to the file structure, component organization, and shared parts of the application.

For the API requests, for example, I created custom functions and templates for GET, POST, PUT, and DELETE that I could reuse across different parts of the project.

The project had more than 60 APIs for retrieving information, creating new records, updating data, and handling other operations. I received the API documentation through Swagger, tested the requests, and then implemented them in the application.

Along the way, I also learned how to handle credentials in API requests and gained a much better understanding of how the frontend and backend communicate.

Another major part of my work involved Ant Design.

I really enjoyed working with the library. It was especially useful for an admin project with this many pages and so much data.

I used a lot of its features throughout the project, from tables and layouts to forms, responsive pages, and built-in transitions.

But one part that took a huge amount of my time was styling the components.

Many of the designs looked very different from Ant Design's default appearance, so I had to override and adjust a lot of its built-in styles with CSS and SCSS.

I think more than half of the time I spent styling the project went into fine-tuning the appearance of Ant Design components!

I also discovered skeleton loading while working on this project and really liked it. Whenever the application needed to fetch information from the server or complete an asynchronous operation, I used dynamic loading states so users could still see the structure of the page while they waited.

Technically, the project was a really valuable experience for me. But there was one part of the collaboration I didn't enjoy very much: the way work was organized at the company.

Before this collaboration, I had worked at MelkRadar and was used to a fully team-based environment where developers, testers, designers, and other people were constantly communicating and moving the work forward together.

That kind of environment didn't exist here.

The work was managed through Jira. I would see my tasks there, complete them, log the time I'd spent on them, and eventually deliver them for testing.

Some tasks were created by the project manager, some by the backend developer, and sometimes I created tasks myself for work that needed to be done.

Most of my communication was with the backend developer and the project manager.

Honestly, I didn't enjoy that way of working very much. I was used to an environment where I could discuss problems with other people, ask for help, and move a project forward as a team.

A lot of that communication was missing here, and that was a new experience for me.

On the other hand, it also meant I had more responsibility. There was no one working alongside me on the frontend, so for many problems I had to research, make decisions, and move the work forward on my own.

There's another interesting detail about when I built this project.

AI tools at the time weren't like they are today. They couldn't connect to VS Code, understand the structure of an entire project, and build new parts based on the code you'd already written.

So I wrote almost all of the project's code myself and by hand, from the initial structure and components to API integrations, data management, and styling.

After around seven months, the main parts of the project were ready, and the company could move on to marketing and the next stages of the product. I delivered my work, and my collaboration with the company came to an end.

Overall, I had a good experience working with Dadeh Pardazi Azmoudeh Karan. The work environment and team communication weren't something I particularly enjoyed, but technically, the project taught me a lot.

For the first time, I had complete responsibility for the frontend of a large React project, from scratch all the way to delivery. Despite all the problems I ran into along the way, I ended up building a clean, high-quality project that I was genuinely happy with.
