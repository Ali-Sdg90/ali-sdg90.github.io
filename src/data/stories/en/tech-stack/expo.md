My main experience with Expo came from building SettleItGPT in 2025.

The project was an iOS application I built with a friend using React Native and Expo.

Expo was a major part of how we worked with the mobile side of the project. The app needed access to native capabilities like the camera, microphone, and photo library, while also handling user accounts, Firebase data, AI integrations, and subscriptions through Stripe.

SettleItGPT was a fairly complicated project, and this was also my first time working this deeply with Expo.

Unlike technologies I had learned gradually through smaller experiments, I had to learn Expo while already building a real product. Whenever the project needed something new, I had to understand how Expo handled it and then make it work inside the application.

That meant dealing with native permissions, device APIs, configuration, builds, and a lot of small mobile-specific problems I hadn't worked with before.

It wasn't always a smooth experience, and I ran into plenty of problems along the way.

But Expo made it possible for us to build a React Native application with all of those native capabilities while still working mostly inside the JavaScript ecosystem I was already familiar with.

Eventually everything came together and we were able to publish SettleItGPT on the Apple App Store.

My relationship with Expo is pretty similar to my relationship with React Native.

I didn't learn it through the gradual process I usually prefer. I learned it because a real project needed it, and I had to keep moving.

But by the end of that project, I knew I could use Expo to take a real mobile application from development all the way to release.

It's not one of the tools I feel especially attached to, but I'm comfortable enough with it to know that if another project needs it, I can work with it and figure out what I need.
