I first came across REST APIs through the CS Internship program, although I didn't really understand them at the time.

My first real experience came while building a Rick and Morty Characters project for a practice challenge.

That was where concepts like GET requests, asynchronous operations, waiting for responses, and actually doing something with the returned data started to make sense to me.

I practiced with APIs in a few personal projects after that, but most of my real learning happened while building a large admin panel for Dadeh Pardazi Azmoudeh Karan.

I was suddenly given more than 60 APIs that the entire frontend had to work with.

I ended up working with almost every part of the usual CRUD flow: reading data, creating records, updating them, deleting them, and keeping all of that manageable inside a fairly large application.

I structured the API layer of the project in a modular way so different parts of the system could stay organized as the project grew.

Authentication was another part I hadn't worked with much before.

A lot of the requests needed authentication data to be attached to them, and I implemented that part with Axios. After working with requests, headers, authentication, responses, and error handling throughout the project, the whole frontend-to-backend flow finally became natural to me.

After that, APIs became part of almost everything I built.

I used them in CS Internship bots, Fabrexa AI, Android and iOS applications, backend services, and different internal tools.

Later, I also started working with React Query and useQuery, and I really liked how much cleaner it made asynchronous data handling.

I think you need to build this stuff manually with fetch at least once to really appreciate tools like Axios and especially React Query.

When you've had to manage loading states, data, errors, retries, request timing, and all the state changes around a request yourself, you understand exactly how much work those tools are taking off your hands.

REST APIs are one of those things I don't think you fully learn just by reading about them.

You need to actually work with them in real projects until the way they behave becomes part of how you think.

At this point, I'm very comfortable with them and see API communication as one of the most natural parts of building a real application.
