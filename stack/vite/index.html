Vite

Frontend Build Tooling

Use Vite as my default setup for modern React projects, with a fast development experience, simple configuration, and efficient builds.

Where It Helps

  • Starting React projects with a fast and lightweight development environment
  • Managing project configuration, builds, aliases, plugins, and environment settings
  • Keeping development and production workflows simple, modern, and performant

Story

I started working with Vite in late 2024.

Before that, I had spent a long time building my React projects with Create React App and had gotten pretty used to its structure.

When I discovered Vite, I quickly noticed how much easier it was to set up a project, how much faster and lighter the development experience felt, and how much better its build process was for my needs. So I pretty much switched completely from CRA to Vite.

Learning it wasn't particularly complicated compared to what I already knew. I mostly needed to get familiar with the project structure, the vite.config file, the build process, and some of Vite's own features.

After that, I started almost all my new React projects with Vite, from larger projects I built for MelkRadar to this portfolio and many others.

While working on MelkRadar projects and this portfolio, I also got familiar with writing tests in Vite-based projects. It wasn't very different from what I had previously done with Jest, so getting comfortable with it was pretty easy.

In this portfolio, when I decided to add SSG and prerendering, I got more involved with Vite's build process and capabilities. It was an interesting experience that took me a bit beyond just using Vite to set up and develop projects.

Recently, I opened one of my old CRA projects again. I couldn't believe how loooong it took to start up for the first time! Obviously not as long as some .NET projects, but compared to Vite, where the development server can be ready in about a second, the difference was really noticeable. :)

Working with Vite feels completely natural to me now, and I usually reach for it without even thinking about it. When starting a new React project, it's pretty much my first choice.

کارم با Vite از پاییز ۱۴۰۳ شروع شد.

قبل از اون مدت زیادی پروژه‌های Reactم رو با Create React App می‌ساختم و به همون ساختار عادت کرده بودم.

وقتی با Vite آشنا شدم، خیلی زود متوجه شدم که هم راه‌اندازی پروژه باهاش راحت‌تره، هم محیط توسعه خیلی سریع‌تر و سبک‌تری داره و هم فرآیند Build بهتری در اختیارم می‌ذاره. برای همین تقریبا کامل از CRA به Vite سوییچ کردم.

یاد گرفتنش هم نسبت به چیزهایی که از قبل بلد بودم خیلی پیچیده نبود. بیشتر لازم بود با ساختار پروژه، فایل vite.config، فرآیند Build و یه سری قابلیت‌های خود Vite آشنا بشم.

بعد از اون تقریبا همه پروژه‌های جدید Reactم رو با Vite شروع کردم. از پروژه‌های بزرگ‌تری که برای ملک‌رادار ساختم گرفته تا همین پورتفولیو و خیلی از پروژه‌های دیگه.

تو پروژه‌های ملک‌رادار و همین پورتفولیو، با تست‌نویسی تو محیط Vite هم آشنا شدم. خیلی با چیزی که قبلا با Jest کار کرده بودم فرق نداشت و برای همین یاد گرفتنش هم برام راحت بود.

تو همین پورتفولیو، وقتی تصمیم گرفتم SSG و Prerendering رو به پروژه اضافه کنم، بیشتر با ساختار Build و قابلیت‌های Vite درگیر شدم. تجربه جالبی بود که باعث شد فراتر از راه‌اندازی و توسعه معمول پروژه‌ها باهاش کار کنم.

تازگی یکی از پروژه‌های قدیمی CRAم رو دوباره باز کردم. باورم نمی‌شد چققققدر طول می‌کشید تا پروژه برای اولین بار بالا بیاد! مشخصا نه به اندازه پروژه‌های .NET، ولی نسبت به Vite که سرور توسعه رو تقریبا تو یه ثانیه بالا میاره، تفاوتش خیلی محسوس بود. :)

الان کار کردن با Vite برام کاملا طبیعیه و تقریبا بدون فکر کردن سراغش می‌رم. برای شروع یه پروژه React جدید هم معمولا انتخاب اولمه.
