Expo

React Native Tooling & Native Integration

Used Expo as the main development layer for SettleItGPT, handling native device capabilities, application configuration, development workflows, and the path toward an iOS App Store release.

Where It Helps

  • Building React Native applications with a simpler development and configuration workflow
  • Accessing native capabilities like the camera, microphone, and photo library
  • Managing mobile app development, native integrations, testing, and release workflows

Story

My main experience with Expo came from building SettleItGPT in 2025.

The project was an iOS application I built with a friend using React Native and Expo.

Expo was a major part of how we worked with the mobile side of the project. The app needed access to native capabilities like the camera, microphone, and photo library, while also handling user accounts, Firebase data, AI integrations, and subscriptions through Stripe.

SettleItGPT was a fairly complicated project, and this was also my first time working this deeply with Expo.

Unlike technologies I had learned gradually through smaller experiments, I had to learn Expo while already building a real product. Whenever the project needed something new, I had to understand how Expo handled it and then make it work inside the application.

That meant dealing with native permissions, device APIs, configuration, builds, and a lot of small mobile-specific problems I hadn't worked with before.

It wasn't always a smooth experience, and I ran into plenty of problems along the way.

But Expo made it possible for us to build a React Native application with all of those native capabilities while still working mostly inside the JavaScript ecosystem I was already familiar with.

Eventually everything came together and we were able to publish SettleItGPT on the Apple App Store.

My relationship with Expo is pretty similar to my relationship with React Native.

I didn't learn it through the gradual process I usually prefer. I learned it because a real project needed it, and I had to keep moving.

But by the end of that project, I knew I could use Expo to take a real mobile application from development all the way to release.

It's not one of the tools I feel especially attached to, but I'm comfortable enough with it to know that if another project needs it, I can work with it and figure out what I need.

تجربه اصلی من با Expo برمی‌گرده به سال ۲۰۲۵ و پروژه SettleItGPT.

این پروژه یه اپ iOS بود که با یکی از دوست‌هام با React Native و Expo ساختیم.

Expo بخش مهمی از کار ما با قسمت موبایل پروژه بود. اپ نیاز داشت به قابلیت‌های Native گوشی مثل دوربین، میکروفون و گالری دسترسی داشته باشه و همزمان سیستم اکانت، اطلاعات Firebase، ارتباط با مدل‌های AI و خرید اشتراک با Stripe رو هم مدیریت کنه.

SettleItGPT پروژه نسبتا پیچیده‌ای بود و این اولین باری هم بود که انقدر جدی با Expo کار می‌کردم.

برخلاف خیلی از تکنولوژی‌هایی که اول با پروژه‌های کوچیک یاد گرفتم و بعد آروم آروم رفتم سراغ چیزهای بزرگ‌تر، اینجا Expo رو وسط ساخت یه محصول واقعی یاد می‌گرفتم. هرجا پروژه به قابلیت جدیدی نیاز داشت، باید می‌فهمیدم Expo چجوری اون قسمت رو مدیریت می‌کنه و بعد پیاده‌ش می‌کردم.

از Permissionهای Native و APIهای گوشی گرفته تا Configuration، Build و یه عالمه مشکل ریز مخصوص دنیای موبایل.

روند خیلی راحتی نبود و تو مسیر هم زیاد به دردسر خوردم.

ولی Expo این امکان رو بهمون داد که یه اپ React Native با کلی قابلیت Native بسازیم و در عین حال بخش زیادی از کار رو داخل همون اکوسیستم JavaScriptای پیش ببریم که خودم باهاش راحت بودم.

در نهایت همه چیز کنار هم قرار گرفت و تونستیم SettleItGPT رو روی Apple App Store منتشر کنیم.

رابطه‌م با Expo تقریبا شبیه رابطه‌م با React Native هست.

اون مسیر آروم و مرحله‌به‌مرحله‌ای که معمولا برای یاد گرفتن یه تکنولوژی دوست دارم رو باهاش طی نکردم. یه پروژه واقعی بهش نیاز داشت و من هم مجبور شدم همزمان یاد بگیرم و جلو برم.

ولی در پایان پروژه می‌دونستم که می‌تونم با Expo یه اپ واقعی رو از مرحله توسعه تا انتشار پیش ببرم.

جزو ابزارهایی نیست که وابستگی خاصی بهش داشته باشم، ولی به اندازه کافی باهاش راحتم که اگه پروژه دیگه‌ای بهش نیاز داشته باشه، می‌دونم می‌تونم کارم رو باهاش پیش ببرم.
