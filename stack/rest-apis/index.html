REST APIs

API Integration & Data Flow

Worked extensively with REST APIs across frontend, backend, mobile, automation, and AI projects, handling CRUD operations, authentication, errors, asynchronous data flow, and service integrations.

Where It Helps

  • Connecting frontend, backend, mobile apps, bots, and external services together
  • Handling CRUD operations, authentication, headers, errors, and asynchronous data flows
  • Structuring API layers cleanly with tools like fetch, Axios, and React Query

Story

I first came across REST APIs in 2023 through the CS Internship program.

At the time, I understood that a request was sent and a response came back, but the mental model behind it, the asynchronous flow, and the purpose of the different HTTP methods hadn't fully clicked for me yet.

My first real experience came while building a Rick and Morty Characters project for a practice challenge.

That was where concepts like GET requests, asynchronous operations, waiting for responses, and actually doing something with the returned data started to make sense to me.

I practiced with APIs in a few personal projects after that, but most of my real learning happened while building a large admin panel for Dadeh Pardazi Azmoudeh Karan.

I was suddenly given more than 60 APIs that the entire frontend had to work with.

I ended up working with almost every part of the usual CRUD flow: reading data, creating records, updating them, deleting them, and keeping all of that manageable inside a fairly large application.

I structured the API layer of the project in a modular way so different parts of the system could stay organized as the project grew.

Authentication was another part I hadn't worked with much before.

A lot of the requests needed authentication data to be attached to them, and I implemented that part with Axios. After working with requests, headers, authentication, responses, and error handling throughout the project, the whole frontend-to-backend flow finally became natural to me.

After that, APIs became part of almost everything I built.

I used them in CS Internship bots, Fabrexa AI, Android and iOS applications, backend services, and different internal tools.

Later, I also started working with React Query and useQuery, and I really liked how much cleaner it made asynchronous data handling.

I think you need to build this stuff manually with fetch at least once to really appreciate tools like Axios and especially React Query.

When you've had to manage loading states, data, errors, retries, request timing, and all the state changes around a request yourself, you understand exactly how much work those tools handle for you.

REST APIs are one of those things I don't think you fully learn just by reading about them.

You need to actually work with them in real projects until the way they behave becomes part of how you think.

At this point, I'm very comfortable with them and see API communication as one of the most natural parts of building a real application.

اولین بار تو سال ۲۰۲۳ و از طریق برنامه CS Internship با مفهوم REST API آشنا شدم.

اون موقع خیلی خوب متوجه نمی‌شدم دقیقا چه اتفاقی داره می‌افته. می‌دونستم یه Request فرستاده می‌شه و یه Response برمی‌گرده، ولی هنوز مدل فکری پشتش، Async بودن کار و نقش متدهای مختلف برام جا نیفتاده بود.

اولین استفاده واقعی من از API تو پروژه Rick and Morty Characters بود.

اونجا برای اولین بار مجبور شدم واقعا با گرفتن اطلاعات از یه API کار کنم و کم‌کم مفاهیمی مثل GET، Async بودن عملیات، منتظر موندن برای Response و مدیریت اطلاعاتی که برمی‌گرده برام قابل فهم‌تر شد.

بعد از اون تو پروژه‌های شخصی مختلف بیشتر تمرین کردم، ولی یادگیری اصلی من تو پروژه بزرگی بود که برای شرکت داده‌پردازی آزموده‌کاران ساختم.

یه Admin Panel بزرگ با React بود و یه دفعه بیشتر از ۶۰ API مختلف در اختیارم قرار گرفت که باید کل فرانت پروژه رو روی اون‌ها پیاده می‌کردم.

تقریبا با تمام عملیات‌های اصلی CRUD درگیر بودم. اطلاعات می‌گرفتم، می‌ساختم، تغییر می‌دادم و حذف می‌کردم و باید همه این‌ها رو به شکل مرتب و قابل نگهداری داخل یه پروژه خیلی بزرگ مدیریت می‌کردم.

برای همین ساختار APIها رو تو پروژه به شکل ماژولار پیاده کردم تا هر بخش جای مشخص خودش رو داشته باشه و با بزرگ‌تر شدن پروژه همه چیز قابل مدیریت بمونه.

یکی از بخش‌هایی که قبل از اون تجربه زیادی باهاش نداشتم Authentication بود.

خیلی از Requestها نیاز داشتند اطلاعات احراز هویت همراهشون ارسال بشه و تو این پروژه با Axios این بخش رو پیاده کردم. انقدر در طول پروژه با Request، Header، Authentication و Error Handling کار کردم که مدل ارتباط Frontend و Backend برام کاملا جا افتاد.

بعد از اون API تقریبا تو همه پروژه‌هام حضور داشت. از بات‌های CS Internship و Fabrexa AI گرفته تا اپ‌های Android و iOS، Backendها و ابزارهای داخلی مختلف.

بعدتر تو یکی از پروژه‌های تمرینیم با React Query و useQuery هم آشنا شدم و خیلی جذب راحتی کار باهاش شدم.

فکر کنم باید حداقل یه بار همه چیز رو با fetch دستی پیاده کرده باشی تا واقعا بفهمی Axios و مخصوصا React Query چقدر می‌تونند کارت رو راحت کنند.

وقتی خودت Loading، Data، Error، Retry، زمان Request و تغییر Stateهای مختلف رو هندل کرده باشی، تازه می‌فهمی این ابزارها دقیقا چه حجم کاری رو از دوشت برمی‌دارند.

REST API برای من یکی از اون مفاهیمیه که فقط با خوندن درباره‌ش واقعا یاد گرفته نمی‌شه.

باید تو پروژه‌های واقعی باهاش درگیر بشی تا مدل فکر کردنش برات جا بیفته.

من الان باهاش کاملا راحتم و ارتباط با APIها رو یکی از طبیعی‌ترین بخش‌های ساخت یه پروژه واقعی می‌بینم.
