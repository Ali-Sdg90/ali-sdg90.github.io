GitHub Actions

CI/CD & Workflow Automation

Built CI/CD workflows with GitHub Actions to automate testing, versioning, releases, builds, deployments, changelogs, notifications, and Android app signing across personal, open-source, and production projects.

Where It Helps

  • Automating tests, builds, versioning, releases, changelogs, and deployments
  • Protecting production workflows by validating changes before they reach live environments
  • Removing repetitive release work and keeping project delivery predictable and maintainable

Story

I started working seriously with GitHub Actions in early 2025 while building CS Queue Calendar.

The project lived inside the CS Internship organization, and I didn't see it as just another small project. It was something that was supposed to stay around after I left and continue being developed and maintained by the program for years.

Because of that, I wanted to build it as professionally and cleanly as I could. I wanted to leave behind something that didn't just work today, but would also be easy to maintain and develop later.

CI/CD was one of the things I discovered while working toward that goal.

My first CI/CD setup was already fairly complete.

Whenever new code was pushed, it would first run the tests I had defined for the project. If everything passed, the workflow would determine the next version through Semantic Release, create a new release, build the application, and deploy the new version to GitHub Pages.

Once I got the whole flow working, I fell in love with how automated it was.

It felt like building a well-oiled machine. I would push my code on one side, and on the other side the system would test it, create the version, publish the release, build the project, and deploy it automatically.

Later, I even added Telegram notifications. After each workflow run, it would send a message to the program's mentors group and report whether the CI/CD process had succeeded or failed.

I later built similar workflows for two other major CS Internship projects, CS Queue Bot and CS Club Bot.

At that point, CI/CD wasn't just a cool feature anymore. It had become part of how we protected the live versions of those projects. Changes were checked before reaching production, and if something went wrong, the people responsible were notified.

Gradually, this way of working became one of my own standards.

For almost every serious project I built after that, I tried to set up the right CI/CD workflow early so repetitive work in the future could be automated and releasing a project wouldn't depend on manually following a long list of steps.

I also built CI/CD workflows for projects I developed for companies, depending on what each project needed.

One of my favorite setups was in Health Data Relay.

GitHub Actions could build the Android application, sign the APK using my own developer signing setup, and publish the finished version as a release.

Even this portfolio you're looking at has its own CI/CD workflow. Semantic Release handles versioning, releases and changelogs are generated automatically, and the project is built and deployed without me having to manually go through the release process.

GitHub Actions is one of those tools I genuinely enjoy working with.

I like the automation itself, but I especially like spending time designing a process once and then knowing the project can repeat that process cleanly and predictably without depending on me doing everything by hand.

I think I have a strong understanding of GitHub Actions at this point, and it's definitely one of the first things I'll consider adding to serious projects in the future.

اولین بار اوایل سال ۲۰۲۵ تو پروژه CS Queue Calendar جدی رفتم سراغ GitHub Actions.

این پروژه روی Organization برنامه CS Internship قرار داشت و برای من فقط یه پروژه معمولی نبود. چیزی بود که قرار بود بعد از من هم بمونه و سال‌ها توسط برنامه توسعه داده و نگهداری بشه.

برای همین از اول می‌خواستم تا جایی که می‌تونم حرفه‌ای و استاندارد بسازمش. چیزی تحویل بدم که فقط امروز کار نکنه، بلکه بعدا هم نگهداری و توسعه‌ش راحت باشه.

یکی از چیزهایی که تو همین مسیر باهاش آشنا شدم CI/CD بود.

اولین CI/CDم رو هم از همون اول نسبتا کامل ساختم.

وقتی کد جدید Push می‌شد، اول تست‌هایی که برای پروژه نوشته بودم اجرا می‌شدند. اگه همه چیز درست بود، سیستم با توجه به Semantic Release نسخه بعدی پروژه رو مشخص می‌کرد، Release جدید می‌ساخت، Build می‌گرفت و نسخه جدید رو روی GitHub Pages منتشر می‌کرد.

وقتی برای اولین بار کل این جریان رو درست کردم، عاشق اتوماتیک بودنش شدم.

حسش برام شبیه ساختن یه ماشین خوب روغن‌کاری‌شده بود. من این طرف کدم رو Push می‌کردم و اون طرف سیستم خودش تست می‌کرد، Version می‌زد، Release می‌ساخت و پروژه رو Deploy می‌کرد.

بعد حتی Notification تلگرام هم بهش اضافه کردم. بعد از اجرای Workflow، تو گروه منتورهای برنامه پیام می‌فرستاد و مشخص می‌کرد CI/CD موفق بوده یا مشکلی پیش اومده.

بعدتر برای دو پروژه بزرگ دیگه برنامه، CS Queue Bot و CS Club Bot، هم Workflowهای مشابه ساختم.

اینجا CI/CD دیگه فقط یه قابلیت باحال نبود. تبدیل شده بود به بخشی از مراقبت از نسخه Live پروژه. قبل از اینکه تغییر جدید وارد نسخه اصلی بشه، یه سیستم خودکار وجود داشت که کارها رو بررسی می‌کرد و اگه مشکلی پیش میومد به افراد مسئول خبر می‌داد.

کم‌کم این مدل کار کردن تبدیل شد به استاندارد خودم.

تقریبا هر پروژه جدی‌ای که می‌ساختم، سعی می‌کردم از همون اول CI/CD مناسب خودش رو هم براش آماده کنم تا کارهای تکراری آینده اتومات بشن و Release کردن پروژه وابسته به یه لیست از کارهای دستی نباشه.

برای بعضی از پروژه‌هایی که برای شرکت‌ها ساختم هم بسته به نیاز پروژه Workflowهای مناسب خودشون رو طراحی کردم.

یکی از نسخه‌های مورد علاقه‌م تو پروژه Health Data Relay بود.

اونجا GitHub Actions خودش اپ اندروید رو Build می‌کرد، فایل APK رو با امضای دولوپری خودم Sign می‌کرد و بعد نسخه آماده رو به‌عنوان Release منتشر می‌کرد.

حتی همین پورتفولیویی که الان دارین می‌بینین هم CI/CD خودش رو داره. با Semantic Release نسخه جدید مشخص میشه، Release و Changelog ساخته میشه و Build و Deploy پروژه هم به‌صورت خودکار انجام میشه.

GitHub Actions یکی از اون ابزارهاییه که واقعا کار کردن باهاش رو دوست دارم.

هم از خود اتوماسیون لذت می‌برم، هم از اینکه یه بار برای یه پروسه درست وقت می‌ذارم و بعد از اون پروژه می‌تونه بارها بدون دخالت من همون کار رو تمیز و قابل پیش‌بینی انجام بده.

فکر می‌کنم تسلط خیلی خوبی بهش دارم و مطمئنا یکی از اولین چیزهاییه که تو پروژه‌های جدی آینده‌م هم اضافه خواهم کرد.
